# Asset prompts — workflow

This folder is how Merlin's Wrath (working title — changes after `e39-title-decision`; the story bible
recommends *Nightjar*) gets consistent art, 3D, music and sound from generative tools and CC0
sources without an art team. **Claude does the production work; the owner approves at explicit gates.**
Consistency is defined **once** in the bibles and enforced by **templates**:

- `docs/narrative/story-bible.md` — **story canon**: every name, location, creature, motif and asset-id subject
  in a prompt must match it (e.g. `horn`, `deepworks`, `knot`, `hushling`).
- `docs/art/style-bible.md` — visual rules + **GPT STYLE PREAMBLE** (§14), per-category add-ons, production workflow (§17).
- `docs/audio/audio-bible.md` — audio rules + **SUNO STYLE PREAMBLE** (§4.1), **SFX PREAMBLE** (§8), workflow (§9).
- `_templates/` — one template per asset category.
- `<category>/<asset-id>.md` — one filled prompt file per asset (or tight asset set).

## Who does what

| Asset kind | Generated by | Tool | Owner gate(s) (`needs-human`) |
|---|---|---|---|
| 2D images (concept, texture, UI, icons, portraits, books, VFX, sky, key art) | **Claude** | `e37-image-gen-runner`: `codex exec` (Codex CLI signed in with the owner's ChatGPT subscription, built-in gpt-image) → fallback OpenAI Images API (`OPENAI_API_KEY`) | Image approval |
| 3D models (hero creatures, bespoke NPCs, unique props) | **Claude** | `e37-3d-gen-api-client`: Meshy or Tripo API (per `e37-3d-pipeline-decision`) | Flat-concept approval **and** turntable approval |
| Bulk props / environments | **Claude** | CC0 kits, recoloured via palette atlas | Covered by style-consistency review |
| Music | **Owner in Suno** (~1 min per track) from Claude's prompt | Suno, paid tier | Picking the take *is* the gate |
| SFX | **Claude** | `e38-sfx-gen-client`: ElevenLabs Sound Effects API; CC0 fallback | SFX batch listening approval |

The owner does **no 3D work, no image editing and no audio editing.**

## Lifecycle

```
prompt bead ─► generate (Claude-run; music = needs-human) ─► APPROVAL GATE(s) (needs-human)
                                                                 │
                     commit source + CREDITS.md row + approvals.json record
                                                                 │
                     integrate bead (pipeline + validator, replaces placeholder) ◄── consuming gameplay bead
```

Gameplay never waits on final assets — it ships with placeholders first (contract §5).

### 2D image

1. **Prompt bead** — Claude copies the template to `assets/prompts/<category>/<asset-id>.md`, fills it, pastes
   the preamble verbatim.
2. **Generate** (Claude) — `e37-image-gen-runner` runs `codex exec` with the prompt file; output lands in
   `~/.codex/generated_images/` and is copied to `assets/_incoming/<asset-id>/vN.png` with `vN.json`
   (prompt file, tool, model, date). Claude self-checks against the checklist and iterates (iteration log).
3. **Gate** — the owner approves/rejects version N; Claude records it in `assets/approvals.json`.
4. **Commit** — approved file promoted to `assets/source/<category>/<asset-id>/`, CREDITS row, pipeline, validator.

### 3D model (style bible §17.2)

concept image (GPT) → **OWNER GATE: flat image** → Claude calls image-to-3D API → remesh/retopo to the tri
budget → rig + animations via API where applicable → download .glb to `assets/_incoming/` → automated
validation (budgets, naming, licence) → Claude renders a **turntable preview** (headless PNG strip + GIF,
`e37-turntable-preview`) → **OWNER GATE: turntable** → commit with provenance in `CREDITS.md`.

### Music

Claude writes the full Suno prompt (Style = preamble + tags, Exclude styles, structure-only Lyrics, key, BPM,
metre, length). The owner pastes it into Suno (paid tier — required for distribution rights), picks the best
take and drops the WAV in `assets/_incoming/music/<asset-id>.wav`. Claude does the rest: trim, loop points,
loudness normalisation, Opus/AAC encode, validation, CREDITS, approval record, integration.

### SFX

Claude generates via the ElevenLabs Sound Effects API (or sources CC0), runs the pipeline, and presents a batch
for the owner to listen to; approved sounds are committed with CREDITS + approval records.

## Rules

- **Asset id = filename stem**, `<category>-<subject>-<variant>`, lower-kebab-case (contract §6).
- **Never paraphrase a preamble.** To change one, change the bible (via a bead), bump its version, note it in
  affected prompt files. The validator checks verbatim use.
- **Reference images are our own.** Attach previously approved repo assets as series anchors; never upload
  third-party art, never name artists, studios or games in prompts.
- **No text in images.** Book, sign and UI text is rendered by the game with our fonts.
- **Secrets:** API keys come only from env vars (`OPENAI_API_KEY`, `MESHY_API_KEY`, `TRIPO_API_KEY`,
  `ELEVENLABS_API_KEY`) — never committed, logged, or written to prompt files, iteration logs or sidecars.
- **Usage limits:** the ChatGPT subscription has image limits — generate in planned batches, not bursts; the
  runner backs off on limit errors.
- **Tier matters.** Record the account/API tier used; shipping assets must come from tiers whose terms allow
  free public distribution. Restrictive-tier outputs are placeholders only.
- **One PR per asset or tight asset set**: source file + prompt file update + CREDITS row + approval record.
- `assets/_incoming/` is a staging area for unapproved candidates and should be gitignored.
